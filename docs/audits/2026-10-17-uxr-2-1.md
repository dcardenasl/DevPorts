# UXR-2.1 — Confirmar toda parada manual y detener sin adoptar

**Fecha:** 2026-10-17  
**Estado:** implementada; verificación automatizada completa. No se hizo una parada real de un proceso del usuario.

## Contrato

Todas las rutas manuales de parada usan la misma confirmación: Atención (duplicados y Temporales), Proyectos (principal, duplicados y Temporales), Compartidos, datos sin declarar y procesos sin proyecto. La ficha incluye identidad del proceso o contenedor, puerto y origen. Para recursos compartidos indica los proyectos consumidores; para contenedores de datos aclara qué contenedor se detendrá y que no se borrará ni su volumen ni el contenedor.

Cancelar cierra el diálogo sin enviar una operación. Detener un proceso suelto no lo adopta ni escribe manifiestos. La UI compara la confirmación con la instantánea vigente al aceptar; la operación vuelve a validar el objetivo en el núcleo antes de detenerlo. Un fingerprint completo derivado de la identidad canónica del proceso (PID e inicio) o ID Docker impide que una referencia reutilizada alcance otro objetivo. El puerto y el resto de la expectativa confirmada también deben coincidir. La terminación de procesos conserva la revalidación de identidad antes de cada señal; Docker usa `stop`, nunca `rm`.

Se añadió `target_identity` a la vista de solo lectura y a los tipos/bindings para permitir la revalidación exacta. No se añadieron métodos ni permisos de parada al socket del CLI. Las políticas de parada automática siguen limitadas a instancias de prueba registradas con lease. Detener un proyecto no detiene recursos compartidos.

## Verificación

- `tools/check.sh full`: verde; incluye formato, matriz (37), clippy, pruebas Rust del workspace y `cargo deny`.
- UI con Node 22: lint, typecheck, 32/32 Vitest y build verdes.
- Prueba Rust de motor: una expectativa cuyo puerto cambió se rechaza; una identidad de proceso reemplazada en el mismo PID/puerto no recibe la acción de la referencia anterior.
- UI: cancelación en compartidos y huérfanos sin efectos; confirmación de identidad/puerto/origen/consumidores; cambio de puerto entre vista y aceptación rechazado; Detener separado de Adoptar/Declarar; rutas de duplicados y Temporales cubiertas.
- La comprobación Docker requiere daemon y quedó ignorada por el conjunto completo. Las pruebas de host que crean servidores desechables propios sí los detuvieron y comprobaron su limpieza; no se detuvo ningún servicio del usuario ni se cambió ningún manifiesto.

## Límites y entrega

La evidencia es de UI simulada y pruebas del núcleo; no equivale a una prueba manual Tauri/WebKit o VoiceOver, que sigue en UXR-0/UXR-7.2. UXR-2.2 puede reutilizar `stopExpectation` por objetivo y la misma operación `stop`; las paradas agrupadas conservan un resultado separado por objetivo.
